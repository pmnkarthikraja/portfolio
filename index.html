CI/CD quality and security pipeline

Moving fast on a regulated money platform only works if mistakes get caught before production. I designed the team's GitHub Actions pipeline and pull request rules.

The challenge

A large legacy codebase with an existing lint backlog. Strict gates on everything would block delivery, and no gates would let new debt in.

What I did

  • Parallel jobs for lint, unit tests with coverage, production build, complexity and duplication checks.
  • Shift-left security with gitleaks secret scanning and npm audit dependency checks.
  • Changed-files gating: PRs are blocked only on problems they introduce, not on the legacy backlog.
  • PR rules for branch naming and Jira ticket references, plus Husky pre-commit hooks.
  • An aggregated CI metrics report to track code health run over run.

Impact

New tech debt and leaked secrets blocked at the PR stage, traceable history, and code health the team and leadership could actually see.
